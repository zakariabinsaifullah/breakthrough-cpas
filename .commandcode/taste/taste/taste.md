# Taste
- Wants new code to follow the existing codebase style and conventions ("follow my existing codebase style"). Confidence: 0.9
- Prefers reusing design tokens from theme.json via their CSS custom properties (e.g., `var(--wp--preset--gradient--btcpa-gradient-one)`) rather than hardcoding the same gradient/color again in component CSS — refers to gradients by token name (e.g., "gradient-one") and expects the agent to map that to the theme's CSS variable. Confidence: 0.8
- Prefers implementing features as extensions of core blocks (e.g., core/paragraph, core/heading) rather than custom blocks — asked for a responsive-alignment extension and a Highlight extension. Confidence: 0.6
- Likes responsive/breakpoint-aware settings for spacing and gap attributes in blocks (e.g., responsive item-gap and icon-gap controls). Confidence: 0.6
- When rebranding or renaming across a project, expects the change applied consistently everywhere in the theme, not partially. Confidence: 0.7
- Ports features from a bundled reference theme (e.g., `ref/`) into the current theme rather than rewriting from scratch, expecting the port to be renamed to the current theme's brand and prefix (e.g., `pandora_*` → `btcpa_*`). Confidence: 0.75
- When asked to redesign something "like" a reference file (e.g., an admin page "like @ref/inc/shortcodes-reference.php"), expects the redesign to faithfully mirror the reference's structure and visual design — header with logo/title, stacked cards with badges, example code + copy button, attribute grid columns, footer tip — adapted only by renaming to the theme's brand and prefix, not by inventing a new layout. Confidence: 0.7
- Explicitly scopes ports to only the features wanted — e.g., "skip team related shortcode" — and expects the skipped feature to be removed entirely (no leftover created files or references), not partially built. Confidence: 0.55
- Wants the agent to ask for clarification when it encounters issues during a task, rather than guessing or silently deciding ("If you find any issues, ASK me"). Confidence: 0.9
- When the user explicitly authorizes fixing (e.g., "check my ... file and if find any issues fix"), wants issues fixed directly and reported, not met with clarification questions — the ask-vs-fix behavior is signaled per task. Confidence: 0.5
- Communicates in terse, numbered/bulleted task lists with direct imperatives. Confidence: 0.85
- Specifies exact visual parameters when requesting design changes (e.g., "a bottom 2px underline text decoration with 5px offset", "make the width for the ID column 100px max", "1px solid #DDE2F0 border with 16px inner padding + 20px border radius", "make sure the metas font size is 14px") rather than describing intent vaguely. Confidence: 0.85
- References code locations by @-mentioning file/directory paths (e.g., "@src/blocks/timeline/", "@inc/form.php", "@ref/inc/shortcodes-reference.php") rather than describing them in prose. Confidence: 0.7
- Prefers per-item spacing (e.g., `padding-bottom` on each item) over `flex gap` on the parent container when each item carries its own connector/`::before` styling, and expects the last item to drop the connector. Confidence: 0.5
- Keeps design style variants visually consistent with the base/default style — e.g., the Alternative button should reuse the default button's gradient for its border, changing only the specified attribute (transparent background) rather than introducing new colors. Confidence: 0.8
- Applies design changes to every variant of a component together (e.g., a hover change requested "for default and alternative button styles" should cover both, not just the primary one). Confidence: 0.7
- Prefers minimal, single-property hover states — on hover everything stays identical except the one specified change (e.g., only the gradient direction flips to 180deg), with no other recoloring, movement, or fading. Confidence: 0.8
- Wants hover/state changes to animate smoothly rather than snap — explicitly asks for a short 0.2s transition (e.g., "add a 0.2s transition to make the change smooth") and expects it applied consistently to all affected variants. Confidence: 0.7
- Gradient-border effects on transparent elements must render the gradient only as the border ring, never as the whole element background; if a background layer is required for the technique, it must be transparent (opacity 0) so the fill stays see-through. Confidence: 0.8
- Hover-only effects must be guaranteed absent in the normal state — e.g., a hover gradient border should be defined only inside the `:hover` rule (so it doesn't exist at all until hover) rather than hidden via opacity, which could be overridden or leak. Confidence: 0.7
- Works directly on the main branch and expects all pending working changes to be committed and pushed straight to main (no feature branches or PR workflow) — a bare "push on main" instruction means commit everything (all pending working changes) and push to main in one go. Confidence: 0.95
- Wants local tooling/config directories (e.g., `.commandcode`, alongside existing `.claude`) excluded from distribution builds via `.distignore`, so local-only files never ship in the theme zip — explicitly asked to "add .commandcode in .distignore". Confidence: 0.7
